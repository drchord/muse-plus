## PHASE 0 — Pre-flight (do these BEFORE touching git)

### 0.1 · iCloud provisioning profile — HIGHEST RISK

Build 51 adds `MusePlus.entitlements` with three iCloud keys:
- `com.apple.developer.icloud-container-identifiers`
- `com.apple.developer.icloud-services: [CloudDocuments]`
- `com.apple.developer.ubiquity-container-identifiers`

The CI uses provisioning profile UUID `a33ca022-44cc-4431-92a2-cc5b5100db3a` (hardcoded in `ios-build.yml` and `ExportOptions.plist`). If this profile was created **before** iCloud was enabled on the App ID, the `xcodebuild archive` step will fail with:

```
error: Provisioning profile does not include the
com.apple.developer.icloud-container-identifiers entitlement.
```

**Verification steps (Apple Developer Portal):**

1. Go to [developer.apple.com/account/resources/identifiers](https://developer.apple.com/account/resources/identifiers)
2. Find `com.drchord.museplus` → Capabilities tab
3. Confirm **iCloud** is checked with container `iCloud.com.drchord.museplus` and service **CloudKit** or **iCloud Documents**
4. Go to Profiles → find profile UUID `a33ca022-44cc-4431-92a2-cc5b5100db3a`
5. Confirm the profile was generated **after** iCloud was added to the App ID (check creation date)

**If profile predates iCloud addition:**
1. Developer Portal → Profiles → Edit the profile → Save (regenerates it with current entitlements)
2. Download the `.mobileprovision`
3. Base64-encode it: `base64 -i MusePlus_AppStore.mobileprovision | pbcopy`
4. GitHub → Settings → Secrets → Update `APPSTORE_PROVISIONING_PROFILE` with new value

## PHASE 3 — CI Pipeline (what happens automatically)

### Step 1 · Checkout (`actions/checkout@v4 lfs: true`)
- Clones the repo
- Hydrates LFS objects: `Frameworks/Muse.framework/Muse` (the fat binary, 13.9MB)
- All 7 .m4a files are regular objects (not LFS), hydrated normally

### Step 2 · Select Xcode
- Finds newest Xcode app in `/Applications/` (macos-15 runner has Xcode 16.x)
- Runs `sudo xcode-select -s` to activate it

### Step 3 · Install XcodeGen
```bash
brew install xcodegen
```
Generates `MusePlus.xcodeproj` from `project.yml`. This is the only `.xcodeproj` used — it is NOT committed to the repo.

**XcodeGen processes `project.yml` which:**
- Creates the MusePlus target with all source files under `MusePlus/`
- Includes `MusePlus/Resources/` (the .m4a files land here automatically)
- Wires `MusePlus/MusePlus.entitlements` via `CODE_SIGN_ENTITLEMENTS`
- Links Muse.framework, CoreBluetooth, Accelerate, libc++

### Step 4 · Generate app icons
Python script generates placeholder blue PNG icons at all required sizes into `MusePlus/Resources/Assets.xcassets/AppIcon.appiconset/`. These are not committed; generated fresh each CI run.

### Step 5 · Set build number
```bash
/usr/libexec/PlistBuddy -c "Set :CFBundleVersion ${{ github.run_number }}" MusePlus/Info.plist
```
`CFBundleVersion` = CI run number (e.g., 25291031223 or similar). This is the build number shown in TestFlight. `CFBundleShortVersionString` stays `1.2.0` (from MARKETING_VERSION in project.yml).

### Step 6 · Import distribution certificate
- Decodes `CERTIFICATE_P12` secret (base64) → `/tmp/cert.p12`
- Creates a temporary keychain at `$RUNNER_TEMP/build.keychain`
- Imports the `Apple Distribution` cert into the keychain
- Sets as default keychain for the build process

### Step 7 · Install provisioning profile
- Decodes `APPSTORE_PROVISIONING_PROFILE` secret → `$RUNNER_TEMP/MusePlus_AppStore.mobileprovision`
- Copies to `~/Library/MobileDevice/Provisioning Profiles/`
- xcodebuild will find it by the UUID `a33ca022-44cc-4431-92a2-cc5b5100db3a` referenced in the archive command

### Step 8 · Setup ASC API key
- Writes `ASC_API_KEY` secret to `~/.appstoreconnect/private_keys/AuthKey_9V47M72GKG.p8`
- This key authenticates the upload to App Store Connect (replaces username/password)
- Key ID: `9V47M72GKG`, Issuer ID: `620b8c6b-545b-4fb4-8b7f-4b527a671243`

### Step 9 · Build and archive (most likely failure point)
```bash
xcodebuild archive \
  -project MusePlus.xcodeproj \
  -scheme MusePlus \
  -configuration Release \
  -destination "generic/platform=iOS" \
  -archivePath build/MusePlus.xcarchive \
  DEVELOPMENT_TEAM=YZN764NT86 \
  CODE_SIGN_STYLE=Manual \
  CODE_SIGN_IDENTITY="Apple Distribution" \
  PROVISIONING_PROFILE_SPECIFIER="a33ca022-44cc-4431-92a2-cc5b5100db3a" \
  CURRENT_PROJECT_VERSION=${{ github.run_number }}
```

Output is piped through `xcpretty` for readability. Full log saved to `build/xcodebuild.log`.

**Compile errors surface here.** If accelerometer `.x/.y/.z` bridging is wrong, you'll see:
```
error: value of type 'IXNMuseDataPacket' has no member 'getAccelerometerValue'
```
or a type error on the enum case. Fix, commit, push again.

**iCloud entitlement mismatch surfaces here.** If provisioning profile doesn't include iCloud:
```
error: Provisioning profile "..." doesn't include the com.apple.developer.icloud-container-identifiers entitlement.
```
Fix: update profile in Developer Portal + update GitHub secret (Phase 0.1).

### Step 10 · Export and upload
```bash
xcodebuild -exportArchive \
  -archivePath build/MusePlus.xcarchive \
  -exportPath build/export \
  -exportOptionsPlist ExportOptions.plist \
  -allowProvisioningUpdates \
  -authenticationKeyPath ~/.appstoreconnect/private_keys/AuthKey_9V47M72GKG.p8 \
  -authenticationKeyID 9V47M72GKG \
  -authenticationKeyIssuerID 620b8c6b-545b-4fb4-8b7f-4b527a671243
```

`ExportOptions.plist` specifies: method=app-store, destination=upload (direct to ASC, no local IPA needed). After export, xcodebuild automatically calls `altool`/`notarytool` via the ASC API key to upload.

### Step 11 · On failure: upload build logs
If any step fails, `build/MusePlus.xcarchive/Logs/` and `build/xcodebuild.log` are uploaded as a GitHub Actions artifact named `build-logs`. Download and inspect `xcodebuild.log`.


Or: GitHub → Actions tab → `iOS Build & TestFlight` workflow → latest run.

Expected duration: **12–20 minutes** (brew install + full archive is slow on macOS runners).

### 4.2 · On failure — diagnose from logs

```bash
gh run download <RUN_ID> --name build-logs
# Opens xcodebuild.log — grep for "error:"
grep "error:" build/xcodebuild.log | head -30
```

Common failure patterns and fixes:

| Log message | Cause | Fix |
|-------------|-------|-----|
| `value of type '...' has no member 'x'` | Accelerometer enum case wrong | Change to `.x`/`.y`/`.z` in MuseClient.swift |
| `icloud-container-identifiers entitlement` | Provisioning profile stale | Regenerate profile → update GitHub secret |
| `No such module 'Muse'` | LFS not hydrated / framework path wrong | Check `Frameworks/Muse.framework/Muse` size — should be 13.9MB, not 134 bytes (LFS pointer) |
| `BandPowers init label mismatch` | Wrong label order in EEGPipeline | Match: delta,theta,alpha,beta,gamma,deltaPeak,thetaPeak,alphaPeak,betaPeak,gammaPeak |
| `largeHall` not found | AVAudioUnitReverb preset misspelled | Verify `.largeHall` in ChimeEngine.swift |
| Upload auth failure | ASC API key expired or wrong | Regenerate key in App Store Connect → update `ASC_API_KEY` secret |

### 4.3 · On success

CI job completes green. Log will end with something like:
```
EXPORT SUCCEEDED
Exported MusePlus to: build/export
```
followed by upload confirmation.

## KNOWN LIMITATIONS (not blockers for Build 51)

| Issue | Impact | Future fix |
|-------|--------|-----------|
| `ppgSampleRate = 64.0` is an assumption | BPM off by % if true rate differs | Add runtime rate estimator from packet timestamps |
| AC search picks harmonic if stronger than fundamental | ~2-3% of sessions at 120+ BPM may show half the true rate | Bias toward longer lags, or verify with autocorrelation at 2×bestLag |
| No PPG quality indicator in UI | User sees stale BPM on poor forehead contact | Add signal quality color to heart rate chip |
| `connectedMuse` accessed from both main and queue threads | Pre-existing data race (low probability crash) | Serialize all `connectedMuse` access through `queue` |
| .m4a files not LFS-tracked | Repo grows ~14MB on this commit | Add `*.m4a filter=lfs` to .gitattributes for future audio |
