# B107 Design Spec
**Date:** 2026-05-17  
**Build target:** TF binary 107 (next after current TF 106 = code tag B103)  
**Scope:** Data integrity fixes + physiological signal enhancements + HRV additions + TrendsView rebuild  

---

## Background

Session 2026-05-17_0531 scored 43/100 despite best-in-dataset beta suppression and strong RMSSD. Root cause: `deepFraction=0` → `deepScore=0` → quality capped at 60. BLE stall at 33.4s exceeded the 30s grace period and terminated the session. These findings, plus trend analysis across 16 sessions, drive this spec.

Six independent problem areas addressed:

1. **NDJSONHeader data gaps** — key fields missing from streaming records
2. **physiologicalScore** — independent signal-quality metric decoupled from deep-state gate
3. **Adaptive Kalman qD** — per-session process noise instead of single-session constant
4. **EEGDenoiser live wire-in** — cleaned EEG signal into live depth pipeline
5. **HRV enhancements** — SDNN, SD2, DFA α1
6. **TrendsView rebuild** — path fix + expanded charts

## Section 2: physiologicalScore

**Problem:** Quality score is dominated by `deepFraction` (40/100). Sessions with excellent EEG signal quality and strong HRV response but zero deep-gate crossings score ≤60 max. The binary gate masks physiological progress.

**New field:** `physiologicalScore: Int` — independent metric, range 0–100, stored in `SessionRecord` and `NDJSONFooter`.

### Formula

```
physiologicalScore = clamp(betaZ_component + rmssdResponse_component + signalCoherence_component, 0, 100)
```

**Component 1: betaZ (0–50)**
```
betaZ = (calibrationBetaMean - sessionBetaMean) / max(calibrationBetaStd, 0.10)
betaZ_component = clamp(betaZ / 2.0 * 50.0, 0.0, 50.0)
```
- `calibrationBetaMean` and `calibrationBetaStd` from existing `DepthScore` properties (lines 22–23 DepthScore.swift)
- `sessionBetaMean` = mean frontal beta over main phase samples in SessionRecorder
- Normalizing by 2.0 SD: betaZ=2 → full 50 points. Positive betaZ means beta suppression (frontal beta lower than calibration = good).

**Component 2: rmssdResponse (0–30)**
```
rmssdResponse_component = clamp((sessionRmssd - calibrationRmssd) / max(calibrationRmssd, 1.0) * 30.0, 0.0, 30.0)
```
- `sessionRmssd` = RMSSD over main phase (already computed)
- `calibrationRmssd` = RMSSD during calibration window (new: add to `HRVPipeline`, tracked separately for calibration phase)
- Zero if no HR data available (guard `calibrationRmssd > 1.0`)

**Component 3: signalCoherence (0–20)**
```
signalCoherence_component = frontalGoodFrac * 20.0
```
- `frontalGoodFrac` already computed in SessionRecorder lines 452–473

### Data flow gap: calibrationBetaMean in SessionRecord

`DepthScore.calibrationBetaMean` and `calibrationBetaStd` exist as `private(set)` properties but are **not in `SessionRecord`** and therefore cannot be read by SessionRecorder at session end for the betaZ formula.

**Fix:** Add `attachCalibrationBeta(mean: Float, std: Float)` to SessionRecorder, following the exact pattern of `attachEnterThreshold()` (lines 1282–1294):

```swift
func attachCalibrationBeta(mean: Float, std: Float) {
    queue.async { [self] in
        rec.calibrationBetaMean = mean
        rec.calibrationBetaStd  = std
    }
}
```

Add `calibrationBetaMean: Float?` and `calibrationBetaStd: Float?` to `SessionRecord` struct.

**Call site:** App.swift, inside `calibrationFiredRecording` block (same location as `attachEnterThreshold`):
```swift
recorder.attachCalibrationBeta(mean: scorer.calibrationBetaMean, std: scorer.calibrationBetaStd)
```

**Verification:** After B107 session, `.json` file contains `calibrationBetaMean` as non-zero float.

## Section 3: Adaptive Kalman qD

**Problem:** `KalmanDepth.qD = 0.0022` (line 25, KalmanDepth.swift) was derived from a single session (2026-05-11). This is a fixed constant across all users and sessions, regardless of baseline EEG variability.

**Adaptive approach:** Set `qD` per-session from calibration ECDF variance. Higher variance calibration → higher process noise → Kalman tracks faster. Bounded to prevent pathological behavior.

### DepthScore: compute calibrationEcdfVariance

`DepthScore.finalizeBaseline()` already computes `baselineStd` (= MAD×1.4826). Use this as the variance proxy.

**Add to DepthScore:**
```swift
private(set) var calibrationEcdfVariance: Float = 0.0
```

**Set inside `finalizeBaseline()`, BEFORE `calibrationSamples = []`:**
```swift
// Compute BEFORE clearing — calibrationSamples is nil after this line
calibrationEcdfVariance = baselineStd * baselineStd   // variance from MAD estimator
```

Critical: `calibrationSamples` is cleared at the end of `finalizeBaseline()`. Any variance computation must occur before that line.

### KalmanDepth: make qD mutable and bounded

```swift
// Before (line 25):
private let qD: Float = 0.0022
// After:
var qD: Float = 0.0022
```

**Bounds:** `qD` must be clamped at wire-in time:
```swift
gate.kalman.qD = min(max(scorer.calibrationEcdfVariance * 0.01, 0.0005), 0.020)
```
- Lower bound 0.0005: prevents over-smoothing for extremely stable baselines
- Upper bound 0.020: prevents erratic tracking for high-artifact calibrations
- Scale factor 0.01: maps typical `baselineStd` (~0.15–0.30) to qD range (~0.0015–0.0030). Derived from the original single-session value: session had `baselineStd≈0.22`, qD=0.0022 → scale=0.0022/0.22²≈0.045. Using 0.01 is conservative; revisit after 3+ sessions with logged qD values.

### Wire-in: App.swift calibrationFiredRecording block

```swift
// After attachEnterThreshold call:
gate.kalman.qD = min(max(scorer.calibrationEcdfVariance * 0.01, 0.0005), 0.020)
```

**Verification:** Log `gate.kalman.qD` at session start. Value should vary across sessions.

## Section 4: EEGDenoiser Live Wire-In

**Context:** `EEGDenoiser.swift` is fully implemented (1133 lines) — 3-stage pipeline: SWT db4 soft-threshold (Donoho & Johnstone 1994) + Riemannian Potato (Barachant 2013) + rASR lite (Mullen 2015/Blum 2019). Currently runs as sidecar in `EEGWindowBuffer`; cleaned output not consumed by any downstream code. `eegDenoiseLiveSignal` UserDefault mentioned in denoiser comments but not read.

**Constraint:** Cannot enable by default. Ground truth validation (tap-to-mark) not yet done. Default = off.

### Step 1: cleanedBatch publisher in EEGWindowBuffer

**EEGWindowBuffer.swift** currently emits raw windows to sidecar. Add a publisher for cleaned output:

```swift
let cleanedBatch = PassthroughSubject<[EEGPacket], Never>()
```

In the sidecar path, after `denoiser.denoise(window)` returns cleaned packets, emit to this subject:
```swift
cleanedBatch.send(cleanedPackets)
```

### Step 2: App.swift routing

App.swift currently subscribes raw `eegPacket` packets to `pipeline.process()`. Add:

```swift
private var liveDenoiseSub: AnyCancellable?

// In session setup:
let liveEnabled = UserDefaults.standard.bool(forKey: "eegDenoiseLiveSignal")
if liveEnabled {
    // Route cleaned batch to pipeline
    liveDenoiseSub = eegBuffer.cleanedBatch.sink { [weak self] packets in
        packets.forEach { self?.pipeline.process($0) }
    }
    // Suppress raw path
    rawEEGSub?.cancel()
    rawEEGSub = nil
} else {
    liveDenoiseSub = nil
}
```

**`rawEEGSub`** = existing AnyCancellable for raw eegPacket → pipeline subscription (must be named and stored, not anonymous, for cancellation to work).

**On session end:** Cancel `liveDenoiseSub`, restore `rawEEGSub` for next session.

### Step 3: UserDefault gate

UserDefault `"eegDenoiseLiveSignal"` defaults to `false`. Not exposed in Settings UI in B107 — set via debugger only. Expose in Settings in a future build after validation data collected.

**Invariant (B107+):** Live denoiser path and raw path are mutually exclusive within a session. Never double-process.

## Section 5: HRV Enhancements

**Current state (verified from HRVPipeline.swift):**
- AMPD R-peak detection (Scholkmann 2012) ✓
- RMSSD (ESC/NASPE 1996) ✓
- LF/HF ✓
- SDNN: NOT computed — prerequisite for SD2
- SD2: NOT computed
- DFA α1: NOT computed

### 5A. SDNN

```swift
let sdnn = sqrt(rrIntervals.map { pow($0 - mean, 2) }.reduce(0, +) / Float(n))
```

Standard definition (ESC/NASPE 1996): standard deviation of all NN intervals. Requires the same `rrIntervals` array already used for RMSSD.

### 5B. SD2 (Poincaré)

```
SD1 = RMSSD / sqrt(2)
SD2 = sqrt(2 * SDNN^2 - RMSSD^2 / 2)
```

**Note:** SD1 = RMSSD/sqrt(2) is exact. SD2 formula: `sqrt(2·SDNN² − RMSSD²/2)`. This is the standard Poincaré decomposition (Brennan 2001). Do NOT use `SD2 = sqrt(2*SDNN^2 - SD1^2/2)` — that formula is wrong.

Nil guard: if `2 * pow(sdnn, 2) - pow(rmssd, 2) / 2 < 0` (numerical precision edge case), SD2 = nil.

### 5C. DFA α1 (Peng et al. 1995)

Short-range scaling exponent over box sizes n=4–16 beats. Minimum 200 RR intervals required; return nil if fewer.

**Algorithm:**
1. Integrate RR series: `y[k] = sum(RR[i] - mean(RR)) for i=1..k`
2. For each box size n in [4, 5, 6, 8, 10, 12, 16]:
   - Divide `y` into non-overlapping boxes of length n
   - Fit linear trend in each box (least squares)
   - Compute RMS of detrended residuals → F(n)
3. `α1 = slope of log(F(n)) vs log(n)` via linear regression

Interpretation: α1 ≈ 1.0 = healthy 1/f scaling; < 0.75 = uncorrelated; > 1.5 = non-stationary. Return as `Float?`.

### 5D. Add to SessionSample and NDJSONSample

```swift
// Add to SessionSample (for in-session streaming):
var sdnn: Float?
var sd1: Float?
var sd2: Float?
var dfaAlpha1: Float?

// Add to NDJSONSample (for NDJSON streaming):
let sdnn: Float?
let sd1: Float?
let sd2: Float?
let dfaAlpha1: Float?
```

DFA α1 updates at session end only (requires full RR array). SDNN, SD1, SD2 update on each heartbeat batch like existing RMSSD.

### 5E. calibrationRmssd for physiologicalScore

Add to `HRVPipeline`:
```swift
private(set) var calibrationRmssd: Float = 0.0
private var calibrationRRSamples: [Float] = []
```

During calibration phase (gated by `isCalibrated == false` in DepthScore), append RR intervals to `calibrationRRSamples`. When calibration completes, compute RMSSD from these and store as `calibrationRmssd`. Reset `calibrationRRSamples` after.

**Wire-in:** App.swift must pass the calibration phase signal to HRVPipeline. Simplest: check `!scorer.isCalibrated` in the heartRate update path and call a new `hrv.appendCalibrationRR(interval:)` method.

3. **calibrationRmssd feasibility** — requires App.swift to distinguish calibration-phase HR samples. Verify the timing gate works before implementing physiologicalScore rmssdResponse component. If not feasible in B107, set rmssdResponse=0 and revisit.
4. **DFA α1 for 16-minute sessions** — typical session yields ~130–180 RR at 60 BPM. 200 RR threshold may rarely be met. Monitor nil rate. Consider lowering to 150 after observing real data.
